> 使用一個模組。隨附指令碼由測試平台上使用的指令碼整合而成，之後在同一測試平台上執行（第 12 節）。

## 1 簡介

DDR5 DIMM 提供一條獨立於記憶體匯流排的兩線邊帶（HSCL、HSDA）。在該匯流排上最先回應的是
SPD5118 Hub；它保存模組的 SPD 資料、回報溫度，並將流量轉送到模組本地匯流排上的其他裝置，
例如 PMIC，以及在具燈光的模組上的 RGB 控制器。Hub 以 I2C 模式啟動，可以切換到 I3C。

本筆記說明如何在沒有主機板的情況下，從主機轉接器讀取 Hub 及上述裝置。

### 1.1 範圍

本文件涵蓋：

- 識別 SPD5118 Hub、讀取其溫度感測器，以及讀取 1 KB 的 SPD NVM
- 讀取 PMIC 狀態，僅讀取
- 使用 SETAASA 將 Hub 切換到 I3C、以 SDR 讀取，並使用 RSTDAA 返回 I2C
- 在本測試平台上傳回正確資料的 I3C 速率，以及未傳回正確資料的那個速率
- 位於 Hub 後方的 Corsair RGB 控制器：使其離開韌體更新模式、逐顆 LED 設定顏色，以及啟動硬體效果

本文件不涵蓋：寫入 SPD NVM、透過 I3C 寫入 Hub 暫存器（第 5.3 節說明原因）、來自 Hub 的
帶內中斷（IBI）（已嘗試，未收到）、PEC，以及在 Hub 處於 I3C 模式時存取 RGB 控制器（未嘗試）。

## 2 系統概述

Table: 邊帶上看到的裝置，Hub 處於 I2C 模式，100 kHz

| 位址 | 裝置 | 回應方式 |
|---|---|---|
| `0x50` | SPD5118 Hub | 暫存器指標 + 讀取；單純讀取也會回應 |
| `0x48` | PMIC | 暫存器指標 + 讀取 |
| `0x18` | Corsair RGB 控制器 | **僅限暫存器指標 + 讀取**；單純讀取不會被確認（ACK） |

該模組的 HSA 被設定為 0，使 Hub 位於 `0x50`。Hub 將傳往模組本地匯流排上裝置的傳輸轉送到
主機端；JESD300-5 將這兩個位址欄位稱為本地 ID（local ID）與主機 ID（host ID）。在 I2C 模式下，
這種轉送不需要任何設定。PMIC 與 RGB 控制器都透過它存取。

以下兩個事實決定了下文的所有內容：

- **單純讀取的掃描找不到 RGB 控制器。** 以一位元組讀取掃描 `0x08` 到 `0x77`，只傳回 `0x48` 與
  `0x50`。先寫入暫存器指標再讀取，才能在 `0x18` 找到它。
- **在本測試平台上，Hub 是一個不會被 ENTDAA 發現的 I3C 目標裝置。** 收到 SETAASA 時，它以其
  靜態位址作為動態位址；收到 RSTDAA 時返回 I2C。

Table: Supernova I3C 連接器選擇

|---|---|

## 5 暫存器與協定

### 5.1 I2C 模式下的 SPD5118 Hub

所有存取都是一個一位元組暫存器指標，後接一次讀取。

Table: 使用的 Hub 暫存器

| 暫存器 | 本模組上的讀值 | 意義 |
|---|---|---|
| MR0-1 | `51 18` | 裝置類型，SPD5118 |
| MR2 | `0x14` | 裝置版本 |
| MR5 | `0x03` | 能力：Hub 與溫度感測器 |
| MR11 | `0x00` | I2C 傳統模式：位元 2:0 選擇 NVM 頁，位元 3 選擇 2 位元組定址 |
| MR12-13 | `FF 7F` | NVM 寫入保護，每個 64 位元組區塊一個位元 |
| MR18 | I2C 下為 `0x00`，I3C 下為 `0x20` | 位元 5 = I3C 模式 |
| MR49-50 | 兩個位元組 | 溫度 |

**溫度。** MR50 位元 4:0 與 MR49 位元 7:0 組成一個 13 位元欄位，其中位元 1:0 未使用。其餘
11 位元為二補數，每 LSB 為 0.25 °C：

```python
raw = (((mr50 & 0x1F) << 8) | mr49) >> 2
if raw & 0x400:
    raw -= 0x800
celsius = raw * 0.25
```

在測試平台上，該模組讀值為 27 到 29 °C。其限值暫存器讀值為 55 °C（高）與 85 °C（臨界）。

**NVM。** 1024 位元組的 NVM 由八個 128 位元組的頁組成。在 1 位元組定址下，位元 7 設定的指標
定址 NVM，位元 6:0 為頁內偏移，MR11 位元 2:0 為頁號。讀取全部內容的方法：保存 MR11，依序將
頁 0 到 7 寫入其中，每次從指標 `0x80` 讀取 128 位元組，然後寫回保存的值。MR11 是唯一被寫入的
暫存器。該模組的傾印解碼為位元組 2 = `0x12`（DDR5）與位元組 3 = `0x02`（UDIMM），且位元組 0 到
509 上的 CRC-16（多項式 `0x1021`，初始值 0）與位元組 510 及 511 中儲存的值相符。

**PMIC。** 暫存器 R32 讀值為 `0x80`（穩壓器已啟用），且未設定任何故障位元。PMIC 僅被讀取。

### 5.2 I3C 模式下的 SPD5118 Hub

1. 以 I3C 模式啟動控制器。
2. 廣播 SETAASA，裝置表中包含 `0x50`。MR18 從 `0x00` 變為 `0x20`。
3. 使用暫存器指標以 SDR 讀取：`sdr_read(0x50, n, subaddress=bytes([reg]))`。
4. 廣播 RSTDAA。透過 I2C 讀取時，MR18 再次為 `0x00`。

`init_bus()` 使用 ENTDAA 發現目標裝置，在本測試平台上未能啟動 Hub。請使用 SETAASA。

Table: 1.1 V 下從 Hub 進行的 I3C SDR 讀取，依推挽速率

| 推挽速率 | 結果 |
|---|---|
| 1 MHz | 20/20 |
| 5 MHz | 50/50（首次執行為 20/20） |
| 6.25 MHz | 50/50 |
| 7.5 MHz | 50/50 |
| 10 MHz | 50/50 |
| 12.5 MHz | 9/50 正確；其餘 41 次在成功狀態下傳回錯誤資料 |

12.5 MHz 下的失敗並未被回報為錯誤：讀取已完成，但資料錯誤。轉接板佈線在 1.1 V 下可能是限制
因素。**在較長的邊帶佈線上請使用 4 MHz 或更低。** 已量測 1 MHz（20/20）以及 5 到 10 MHz；兩者
之間的速率未量測。`ddr5_spd.py --i3c` 預設使用 1 MHz。

### 5.3 透過 I3C 寫入暫存器

> **注意：** 在 I3C SDR 模式下對 Hub 的暫存器寫入未依寫入的值生效，隨後匯流排停滯。寫入為
> 26.5 °C 的溫度限值回讀為 48 °C；寫入 MR27 的 `0x01` 回讀為 `0x10`。此後，每個 I3C 操作都傳回
> `FW_I3C_ENGINE_BUSY`。重新開機 Supernova 無法清除該狀態，將 LV 連接器重新上電也不行。只有將
> 模組重新上電才能清除。原因（Hub 的 I3C 寫入格式或主機端）尚未確定。在 I3C 模式下僅進行讀取。
> 若需要寫入，請在 I2C 模式下進行，或先寫入一個無害的暫存器並以回讀確認。

### 5.4 Corsair RGB 控制器

以下暫存器對應表與封包格式來自 OpenRGB 的 Corsair DRAM 控制器（GPL-2.0）。本文件中的指令碼
依據該描述重新實作；未複製任何 OpenRGB 程式碼。在 Hub 處於 I2C 模式時，透過 `0x18` 存取該控制器。

每次存取都是寫入 `[register, value]`，或暫存器指標後接一位元組讀取。**控制器閒置一段時間後的
第一次存取可能被拒絕一次；請重試。**

Table: 使用的 RGB 控制器暫存器

| 暫存器 | 存取 | 用途 |
|---|---|---|
| `0x0B`, `0x21` | 寫入 `0x00` | 重設封包緩衝區及其 CRC |
| `0x20` | 寫入，每次存取一個位元組 | 封包緩衝區 |
| `0x42` | 讀取 | 自重設以來載入之位元組的 CRC-8 |
| `0x82` | 寫入 | 套用：`0x01` 效果封包，`0x02` 顏色緩衝區 |
| `0x30` | 讀取 | 套用過程中位元 3 設定 |
| `0x61` 然後 `0x21` | 寫入 `0x00` | 選擇裝置資訊區塊 |
| `0x40` | 讀取，32 次 | 裝置資訊區塊 |
| `0x23` | 寫入 `0x01` | 離開韌體更新模式 |

CRC 為 CRC-8，多項式 `0x07`，初始值 0。套用之前請將其與 `0x42` 比較；不相符表示有位元組遺失
或重複（重試寫入可能造成此情況），此時不得套用該封包。

**裝置資訊區塊。** 位元組 0-1 為 VID，小端序；位元組 2-3 為 PID；位元組 28 為協定版本。

**韌體更新模式。** 兩端的 LED 都亮紅色，是 Corsair 文件中所述的韌體更新（開機載入程式）模式
指示。在該狀態下，模組回報 PID `0x0B00` 與協定 1，並接受效果封包（CRC 相符），但 LED 不變化。
向 `0x23` 寫入一次 `0x01` 後，它變為 PID `0x0B01`、協定 4，原廠彩虹效果隨之亮起（圖 1）。模組
如何進入該模式尚未確定；它在上電後不久曾被探測過。

> **注意：** 切勿向暫存器 `0x23` 寫入 `0x00`。

![離開韌體更新模式後的模組：原廠彩虹效果。](figures/an0016-fig1-after-bootloader.png)

**顏色緩衝區。** 六個 `R, G, B, 0xFF` 項目，每顆 LED 一個，共 24 位元組，在重設後載入到
`0x20`，檢查 CRC，並以 `0x82` = `0x02` 套用。由此可設定單一顏色與逐顆 LED 顏色（圖 2）。該緩衝區
僅在靜態模式下顯示：在動畫效果下，它會被接受（包括 CRC），但會被忽略。因此
`ddr5_rgb.py color` 會先送出靜態效果（模式 `0x10`）。

![顏色緩衝區：六顆 LED 全部為紅色（左），每顆 LED 一種顏色（右）。](figures/an0016-fig2-colour-buffer.png)

**效果封包。** 20 位元組，以 `0x82` = `0x01` 套用：

```
mode, speed, 0x01, direction, R1, G1, B1, brightness, R2, G2, B2, brightness, 0 x 8
```

Table: 效果模式

| 模式 | 代碼 | 在本模組上觀察到 |
|---|---|---|
| 彩虹波（rainbow wave） | `0x03` | 是 |
| 靜態（static） | `0x10` | 已套用，但維持先前的顏色；請改用顏色緩衝區 |
| 彩虹（rainbow） | `0x08` | 未觀察到 |
| 脈衝（pulse） | `0x01` | 未觀察到 |

## 6 操作程序

### 6.1 上電與連接

透過轉接板為模組供電。將纜線連接到 Supernova I3C LV 連接器。

### 6.2 識別 Hub 並讀取其溫度


```
python ddr5_spd.py --serial <serial>
```

測試平台上的輸出：

```
MR0-1 5118  (SPD5118 reads 5118)
MR2 revision 0x14  MR18 0x00  (bit 5 = I3C mode)
MR49-50 CC 01 = 28.75 C
```

### 6.3 保存 NVM（選用）

將 NVM 保存到您選擇的檔案中。請將該檔案視為可識別該模組的資訊：它包含模組的序號。

```
python ddr5_spd.py --serial <serial> --nvm my_module_spd.bin
```

指令碼會還原 MR11，並回報 SPD CRC 是否相符：

```
MR0-1 5118  (SPD5118 reads 5118)
MR2 revision 0x14  MR18 0x00  (bit 5 = I3C mode)
MR49-50 CC 01 = 28.75 C
NVM: 1024 bytes to my_module_spd.bin, MR11 restored to 0x00
SPD byte 2 0x12 (0x12 = DDR5), byte 3 0x02, CRC 0-509 calc 0x45BF stored 0x45BF OK
```

### 6.4 以 I3C 模式讀取 Hub（選用）

指令碼使用 SETAASA 進入 I3C 模式，以 SDR 讀取，然後使用 RSTDAA 將 Hub 返回 I2C：

```
python ddr5_spd.py --serial <serial> --i3c --i3c-mhz 1
```

在 I3C 讀取期間 MR18 讀值為 `0x20`，RSTDAA 之後為 `0x00`：

```
MR0-1 5118  (SPD5118 reads 5118)
MR2 revision 0x14  MR18 0x00  (bit 5 = I3C mode)
MR49-50 CC 01 = 28.75 C
I3C SDR: MR18 0x20  MR0-1 5118  temperature 29.00 C
after RSTDAA (I2C): MR18 0x00
```

在轉接器韌體 4.6.1 上，每次轉接器重設後此操作可執行 11 次；參見第 9 節。

### 6.5 讀取 RGB 控制器的裝置資訊


```
python ddr5_rgb.py --serial <serial> info
```

測試平台上的輸出，控制器處於一般模式：

```
VID 0x1B1C PID 0x0B01 protocol 4
```

### 6.6 離開韌體更新模式

若 PID 為 `0x0B00`（兩端為紅色），請離開韌體更新模式。指令碼僅在 PID 為 `0x0B00` 時才寫入。

```
python ddr5_rgb.py --serial <serial> leave-bootloader
```

控制器處於韌體更新模式時的輸出：

```
before: PID 0x0B00 protocol 1
after:  PID 0x0B01 protocol 4
```

以及控制器已處於一般模式時的輸出：

```
before: PID 0x0B01 protocol 4
not in firmware-update mode; nothing written
```

### 6.7 設定顏色或效果


```
python ddr5_rgb.py --serial <serial> color 255,0,0
python ddr5_rgb.py --serial <serial> color 255,0,0 255,80,0 255,220,0 0,255,0 0,0,255 160,0,255
python ddr5_rgb.py --serial <serial> effect wave 255,0,0 0,0,255 --speed 2
python ddr5_rgb.py --serial <serial> demo
```

這些命令成功時不輸出任何內容；若控制器的 CRC 不相符，則以錯誤結束。

示範序列見 `figures/an0016-video1-rgb-demo.mp4`（42 s），由該指令碼所整合自的測試平台指令碼錄製。

Table: ddr5_spd.py 選項

| 選項 | 作用 |
|---|---|
| `--serial` | 轉接器序號；預設為找到的第一個轉接器 |
| `--voltage-mv` | 匯流排電壓，預設 1100（LV 連接器） |
| `--nvm FILE` | 透過 MR11 將 1024 位元組 NVM 讀入 FILE，然後還原 MR11 |
| `--i3c` | SETAASA，以 SDR 讀取 MR18、MR0-1 與溫度，RSTDAA |
| `--i3c-mhz` | `--i3c` 的推挽速率：1、3.125 或 5；預設 1 |

Table: ddr5_rgb.py 命令

| 命令 | 作用 |
|---|---|
| `info` | 檢查資訊區塊的 CRC 後，印出 VID、PID 與協定 |
| `leave-bootloader` | 若 PID 為 `0x0B00`，寫入 `0x23` = `0x01`；印出前後的 PID |
| `color R,G,B` | 透過顏色緩衝區將六顆 LED 設為同一種顏色 |
| 帶六個 `R,G,B` 的 `color` | 每顆 LED 一種顏色 |
| `effect MODE C1 [C2]` | 效果封包；MODE 為 static、rainbow、wave 或 pulse；`--speed` 0 到 2 |
| `demo` | 紅、綠、藍、白，逐顆 LED 彩虹，追逐效果，然後彩虹波 |

兩個指令碼對每次存取最多重試三次（`ddr5_spd.py`）或五次（`ddr5_rgb.py`）。

## 9 疑難排解

Table: 疑難排解

| 症狀 | 原因 | 處理 |
|---|---|---|
| 掃描找到 `0x48` 與 `0x50`，但 `0x18` 處沒有裝置 | RGB 控制器不確認單純讀取 | 寫入暫存器指標後讀取，如 `ddr5_rgb.py info` 所做 |
| 對 `0x18` 的第一次存取被拒絕，下一次成功 | 控制器處於閒置狀態 | 重試；指令碼會自動重試 |
| 兩端 LED 為紅色，效果封包被接受但沒有任何變化 | 控制器處於韌體更新模式，PID `0x0B00` | `ddr5_rgb.py leave-bootloader` |
| 之後控制器在未重新上電的情況下又回到韌體更新模式 | 在廣播 CCC 流量（RSTDAA/ENTDAA）與轉接器重設之後出現；原因未查明 | 執行 `ddr5_rgb.py info`；若 PID 為 `0x0B00`，再次執行 `leave-bootloader` |
| 對 Hub 的每次 I2C 讀取都傳回 `51 FF`，無論暫存器為何 | Hub 被之前的 SETAASA 留在 I3C 模式（MR18 位元 5 設定） | 送出 RSTDAA，或將模組重新上電 |
| 多次 I3C 作業後 SETAASA 被拒絕：目標裝置表已滿（見下文） | 轉接器韌體 4.6.1 在 RSTDAA 之後的每次 SETAASA 都新增一個目標裝置表項目；第 12 次失敗（3/3 次執行） | 重設轉接器（`reboot` 或重新插拔）；已在轉接器韌體中追蹤 |
| 顏色被接受（CRC 相符），但 LED 繼續播放動畫 | 控制器正在執行動畫效果；顏色緩衝區僅在靜態模式下顯示 | `ddr5_rgb.py color` 會先選擇靜態模式；使用原始寫入時，請先送出靜態效果，再送出顏色 |
| `0x42` 處 CRC 不相符 | 載入時有位元組遺失或重複 | 重新送出整個封包；不要套用 |
| `init_bus()` 找不到 Hub | 在本測試平台上 Hub 不會被 ENTDAA 發現 | 使用 `ccc.setaasa([0x50])` |
| 完全沒有裝置回應 | 1200 mV 或更高會選擇 HV 連接器 | 要求 1100 mV |
| I3C 模式下資料錯誤但狀態為成功 | 推挽速率相對於佈線過高 | 4 MHz 或更低 |
| I3C 寫入後每個 I3C 操作都傳回 `FW_I3C_ENGINE_BUSY` | Hub 停滯（第 5.3 節） | 將模組重新上電；重新開機 Supernova 無法清除 |
| NVM 傾印 CRC 不相符 | MR11 被變更，或傾印過程中某次讀取失敗 | 重新執行；檢查 MR11 位元 3 為 0 |

目標裝置表已滿導致的拒絕回報為 `FW_NOT_ENOUGH_SPACE_IN_TARGET_DEVICES_TABLE`。

## 10 縮寫

Table: 縮寫

| 術語 | 意義 |
|---|---|
| CCC | 通用命令代碼（Common Command Code，I3C） |
| CRC | 循環冗餘檢查（Cyclic redundancy check） |
| DIMM | 雙列直插式記憶體模組（Dual in-line memory module） |
| ENTDAA | 進入動態位址分配（Enter Dynamic Address Assignment，I3C CCC） |
| HSA | 主機邊帶位址設定腳位（Host sideband address strap） |
| HSCL, HSDA | 主機邊帶時脈與資料（Host sideband clock and data） |
| LED | 發光二極體（Light-emitting diode） |
| LV, HV | Supernova 的低電壓與高電壓 I3C 連接器 |
| MR | SPD5118 的模式暫存器（Mode register） |
| NVM | 非揮發性記憶體（Non-volatile memory） |
| PEC | 封包錯誤檢查（Packet error check） |
| PID, VID | 產品 ID，廠商 ID（Product ID, vendor ID） |
| PMIC | 電源管理積體電路（Power management integrated circuit） |
| RSTDAA | 重設動態位址分配（Reset Dynamic Address Assignment，I3C CCC） |
| SDR | 單倍資料速率（Single data rate，I3C） |
| SETAASA | 將所有位址設為靜態位址（Set All Addresses to Static Address，I3C CCC） |
| SPD | 序列存在偵測（Serial presence detect） |
| UDIMM | 無緩衝 DIMM（Unbuffered DIMM） |
| VIN_BULK | DIMM 的 5 V 輸入電源 |
