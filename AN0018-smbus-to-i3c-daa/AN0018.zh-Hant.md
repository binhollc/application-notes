## 1 簡介

有些裝置上電時作為 3.3 V 的 SMBus 目標裝置運作，並可切換到 1.8 V 的 I3C。何時切換由主機決定：
主機先確認匯流排上剩下的每個裝置都能跟著切換，然後降低匯流排電壓並分配動態位址。僅支援 SMBus
的裝置無法承受這次切換，因此主機只要發現這樣的裝置，就會維持在 SMBus 模式。

Supernova 的 I3C 埠在同樣的兩個接腳上同時支援 SMBus（傳統 I2C）和 I3C，其電壓由軟體設定。
因此，整個流程只需一個埠和一個腳本即可執行。

### 1.1 範圍

本文件涵蓋：

- 流程的五個步驟，以及每個步驟背後的 pyCosmicSDK 呼叫
- 接線，以及匯流排上拉電阻必須接在何處才能隨電壓變化
- 一個執行該流程的腳本，位址分配使用 SETDASA 或 ENTDAA
- 在以一台 Supernova 作為 I3C 裝置的測試平台上的實測結果

本文件不涵蓋 PCI-SIG 頻外管理規範中的 SMBus 到 I3C Basic 偵測流程（熱加入（Hot-Join）、ARP、
SMBus 重設），這部分由 AN0014 說明；也不涵蓋 MCTP 和 NVMe-MI 訊息。

## 2 系統概觀

表 3 列出各個步驟以及執行每個步驟的呼叫。

Table: 流程的步驟

| 步驟 | 動作 | pyCosmicSDK 呼叫 |
|---|---|---|
| 1 | 在 3.3 V 下以 SMBus 模式運作 | `set_voltage(voltage_mv=3300)`、`bring_up(...)`、`ccc.rstdaa()` |
| 2 | 廣播一個 7Eh 命令。收到 ACK 表示匯流排上至少有一個 I3C 裝置 | `ccc.disec_broadcast(I3cEvent.HJ)`；NACK 會引發帶有 `FW_I3C_NACK_ADDRESS` 的 `I3cError` |
| 3 | 探測每個 SMBus 位址。有回應且不是已知 I3C 裝置的裝置即為僅支援 SMBus 的裝置；只要還有一個這樣的裝置，就維持在 SMBus 模式 | 對 08h 到 77h 執行 `legacy_i2c_read(address, 1)` |
| 4 | 將匯流排及其上拉電阻從 3.3 V 切換到 1.8 V | `set_voltage(voltage_mv=1800)` |
| 5 | 使用 SETDASA 或 ENTDAA 分配動態位址，然後讀取每個裝置的 PID | `ccc.setdasa(static=, dynamic=)` 或 `init_bus()`，然後 `ccc.getpid(address)` |

以下三點決定了此流程的形式：

- **步驟 2 是一個 CCC，而不是 SMBus 傳輸。** 只有 7Eh 標頭以開汲極方式送出，因此僅支援 SMBus
  的裝置看到的是一個不屬於自己的位址，並會忽略它。所用的 CCC 是帶 DISHJ 的 DISEC，它同時也能防止
  I3C 裝置在主機仍處於 SMBus 模式時進行熱加入。
- **步驟 3 需要一份 I3C 裝置靜態位址的清單。** 具有靜態位址的 I3C 裝置也會在該位址上回應 SMBus
  讀取，因此僅憑回應並不能證明某個裝置僅支援 SMBus。腳本接收 I3C 裝置的靜態位址（`--i3c-static`），
  並將其他任何回應視為僅支援 SMBus 的裝置。
- **只有當上拉電阻接在埠電壓上時，步驟 4 才會使其隨之切換。** Supernova 的 SDA 上拉電阻跟隨
  I3C 埠電壓。外部上拉電阻只有在接到埠的 VTARG 接腳時才會跟隨（第 3.3 節）。

## 3 硬體設定

### 3.1 所需設備

Table: 所需設備

| 項目 |
|---|
| Binho Supernova，韌體 4.6.0 或更新版本 |
| USB-C 線材 |
| 待測裝置，或用來扮演待測裝置的第二台 Supernova（第 6 節） |
| 接到 VTARG 的上拉電阻（如果匯流排上沒有） |

### 3.2 連接

Table: Supernova I3C HV 埠與裝置之間的連接

| Supernova I3C HV 埠 | 裝置 | 是否必要 |
|---|---|---|
| SCL | SCL | 必要 |
| SDA | SDA | 必要 |
| GND | GND | 必要 |
| VTARG | 上拉電阻，或裝置的 I/O 電源 | 匯流排有外部上拉電阻時必要 |

### 3.3 匯流排注意事項

I3C 埠的 SCL 上沒有上拉電阻，而 SMBus 需要上拉電阻。請將 SMBus 上拉電阻接到埠的 VTARG
接腳，而不是固定的 3.3 V 電源軌。VTARG 跟隨 `set_voltage`，因此步驟 4 會將上拉電阻與匯流排一起從
3.3 V 切換到 1.8 V。接到固定 3.3 V 電源軌的上拉電阻會在步驟 4 之後仍將匯流排維持在 3.3 V，
高於 1.8 V 裝置所能接受的電位。

> **注意：** 不耐受 3.3 V 的裝置在步驟 1 到 3 期間不得接在匯流排上。

> **注意：** 匯流排上只能有一個控制器。

## 4 軟體設定

使用執行腳本的同一個 Python，從 PyPI 安裝最新發行版本的 pyCosmicSDK：

```
python -m pip install --upgrade pycosmicsdk
```

使用 Mission Control 將 Supernova 更新到韌體 4.6.0 或更新版本。

## 5 操作程序

執行腳本時傳入匯流排上每個 I3C 裝置的靜態位址。預設值為：SMBus 使用 3300 mV，I3C 使用 1800 mV，
並使用 SETDASA，從 08h 開始分配動態位址：

```
python smbus_to_i3c_daa.py --i3c-static 0x3A --daa setdasa
python smbus_to_i3c_daa.py --i3c-static 0x3A --daa entdaa
```

輸出會標示每個步驟。在第 6 節的測試平台上：

```
FW-4.6.2 controller | target FW-4.6.2
1. SMBus mode, bus at 3300 mV
2. DISEC to 7Eh: ACK, an I3C device is present
3. SMBus probe 08h-77h: 3Ah -> SMBus-only: none
4. Bus and pull-ups at 1800 mV
5. SETDASA: dynamic 08h, GETPID 0B0000000A01
```

如果沒有裝置對 7Eh 回應 ACK，腳本在步驟 2 之後停止；如果有僅支援 SMBus 的裝置回應，腳本在步驟 3
之後停止。在這兩種情況下，匯流排都維持在 SMBus 電壓。當每個已分配位址的裝置都傳回了其 PID 時，
腳本以 0 結束。

若要在您自己的程式碼中使用此流程，請複製 `run` 函式：每個步驟只有幾行，且只使用表 3 中的呼叫。

Table: smbus_to_i3c_daa.py 選項

| 選項 | 預設值 | 意義 |
|---|---|---|
| `--serial` | 任意 | 控制器 Supernova 的序號（或其前綴） |
| `--i3c-static` | 必要 | I3C 裝置的靜態位址；其他任何 SMBus 回應都視為僅支援 SMBus 的裝置 |
| `--daa` | `setdasa` | `setdasa` 為每個靜態位址分配一個位址；`entdaa` 由韌體為每個裝置分配位址 |
| `--first-dynamic` | 0x08 | SETDASA 分配的第一個動態位址 |
| `--smbus-mv` | 3300 | 步驟 1 到 3 的匯流排電壓 |
| `--i3c-mv` | 1800 | 匯流排電壓，從步驟 4 起 |
| `--settle-ms` | 10 | 電壓變更後的等待時間 |
| `--emulate-target` | 無 | 第二台 Supernova 的序號，它在第一個 `--i3c-static` 位址上扮演 I3C 裝置 |
| `--rounds` | 1 | 將流程執行指定次數，並印出通過的次數 |

### 6.1 測試配置

Table: 測試配置

| 項目 | 值 |

| 主機軟體 | 來自 PyPI 的 pyCosmicSDK 1.6.0，Ubuntu 22.04 |
| 匯流排 | I3C HV 埠之間連接 SCL、SDA、GND |
| 分析儀 | Saleae Logic Pro 16，在 SCL 和 SDA 上擷取類比和數位訊號 |

### 6.2 結果

Table: 結果

| 執行 | 結果 |
|---|---|
| SETDASA，20 次執行 | 20 次中 20 次：7Eh ACK，SMBus 上只有 3Ah，動態位址 08h，PID 讀回 |
| ENTDAA，20 次執行 | 20 次中 20 次：同上，動態位址 08h 由韌體分配 |
| 匯流排高電位，分析儀上的一次執行 | SCL 在步驟 1 到 3 中為 3.34 V，步驟 4 之後為 1.79 V |

步驟 3 中僅支援 SMBus 的分支未在此測試平台上執行，因為此測試平台上沒有僅支援 SMBus 的裝置。
以上是我們在一個測試平台上量測到的數據，並非規格。

## 7 疑難排解

Table: 疑難排解

| 症狀 | 可能原因及處理方式 |
|---|---|
| 匯流排上有 I3C 裝置，但步驟 2 回報 NACK | 裝置未上電，或未處於 SMBus 電壓。請檢查 `--smbus-mv` 和裝置電源。 |
| 步驟 3 將 I3C 裝置列為僅支援 SMBus 的裝置 | `--i3c-static` 中缺少其靜態位址。請加入該位址。 |
| 步驟 3 未發現任何裝置，但步驟 5 仍然成功 | 裝置不在其靜態位址上回應 SMBus 讀取。這不影響此流程。 |
| 步驟 5 的 GETPID 因 `FW_I3C_NACK_ADDRESS` 失敗 | 匯流排電壓仍高於裝置的 I/O 電壓，或裝置不支援所用的 DAA 方法。請檢查上拉電阻是否接到 VTARG，或嘗試另一個 `--daa`。 |
| 步驟 4 之後匯流排仍為 3.3 V | 外部上拉電阻接在固定的 3.3 V 電源軌上。請將其接到 VTARG（第 3.3 節）。 |

## 8 縮寫

Table: 縮寫

| 術語 | 意義 |
|---|---|
| I3C | MIPI Improved Inter-Integrated Circuit |
| SMBus | System Management Bus（系統管理匯流排） |
| CCC | I3C 共用命令碼（common command code） |
| DISEC | 停用目標裝置事件的 CCC，此處為熱加入（DISHJ） |
| SETDASA | 為具有靜態位址的裝置分配動態位址的 CCC |
| ENTDAA | 為每個裝置啟動動態位址分配的 CCC |
| RSTDAA | 重設所有動態位址的 CCC |
| GETPID | 讀取裝置 48 位元暫時 ID 的 CCC |
| PID | 暫時 ID（Provisional ID） |
| BCR、DCR | I3C 匯流排特性暫存器和裝置特性暫存器 |
| VTARG | Supernova I3C 埠的電源輸出，電壓等於埠電壓 |
