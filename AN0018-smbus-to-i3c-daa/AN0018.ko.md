## 1 소개

일부 디바이스는 3.3 V의 SMBus 타깃으로 전원이 켜지고 1.8 V의 I3C로 전환할 수 있습니다. 전환 시점은
호스트가 결정합니다. 호스트는 먼저 버스에 남아 있는 모든 디바이스가 전환을 따를 수 있는지 확인한 다음,
버스 전압을 낮추고 동적 주소를 할당합니다. SMBus만 지원하는 디바이스는 이 전환을 견딜 수 없으므로,
그러한 디바이스를 발견하면 호스트는 SMBus 모드를 유지합니다.

Supernova의 I3C 포트는 동일한 두 핀에서 SMBus(레거시 I2C)와 I3C를 모두 지원하며, 그 전압은
소프트웨어에서 설정합니다. 따라서 전체 시퀀스를 하나의 포트와 하나의 스크립트로 실행할 수 있습니다.

### 1.1 범위

이 문서는 다음을 다룹니다.

- 시퀀스의 다섯 단계와 각 단계에 사용되는 pyCosmicSDK 호출
- 배선, 그리고 버스 풀업이 전압 변경을 따르도록 하기 위해 연결해야 하는 위치
- 주소 할당에 SETDASA 또는 ENTDAA를 사용하여 시퀀스를 실행하는 스크립트
- Supernova를 I3C 디바이스로 사용한 벤치에서의 측정 결과

PCI-SIG 대역 외 관리 사양의 SMBus에서 I3C Basic으로의 검출 흐름(핫 조인(Hot-Join), ARP, SMBus
리셋)은 AN0014에서 다루므로 이 문서에서는 다루지 않으며, MCTP 및 NVMe-MI 메시지도 다루지 않습니다.

## 2 시스템 개요

표 3은 각 단계와 이를 수행하는 호출을 나열합니다.

Table: 시퀀스의 단계

| 단계 | 동작 | pyCosmicSDK 호출 |
|---|---|---|
| 1 | 3.3 V에서 SMBus 모드로 동작 | `set_voltage(voltage_mv=3300)`, `bring_up(...)`, `ccc.rstdaa()` |
| 2 | 7Eh 명령을 브로드캐스트합니다. ACK는 버스에 I3C 디바이스가 하나 이상 있음을 의미합니다 | `ccc.disec_broadcast(I3cEvent.HJ)`; NACK이면 `FW_I3C_NACK_ADDRESS`와 함께 `I3cError`가 발생합니다 |
| 3 | 모든 SMBus 주소를 프로브합니다. 응답하면서 알려진 I3C 디바이스가 아닌 디바이스는 SMBus 전용입니다. 그러한 디바이스가 남아 있으면 SMBus 모드를 유지합니다 | 08h부터 77h까지 `legacy_i2c_read(address, 1)` |
| 4 | 버스와 그 풀업을 3.3 V에서 1.8 V로 전환 | `set_voltage(voltage_mv=1800)` |
| 5 | SETDASA 또는 ENTDAA로 동적 주소를 할당한 다음 각 디바이스의 PID를 읽습니다 | `ccc.setdasa(static=, dynamic=)` 또는 `init_bus()`, 그다음 `ccc.getpid(address)` |

다음 세 가지 사실이 시퀀스의 형태를 결정합니다.

- **단계 2는 SMBus 전송이 아니라 CCC입니다.** 7Eh 헤더만 오픈 드레인으로 전송되므로, SMBus 전용
  디바이스는 자신의 것이 아닌 주소를 보고 이를 무시합니다. 사용되는 CCC는 DISHJ를 지정한 DISEC이며,
  호스트가 아직 SMBus 모드에 있는 동안 I3C 디바이스가 핫 조인하는 것도 막아 줍니다.
- **단계 3에는 I3C 디바이스의 정적 주소 목록이 필요합니다.** 정적 주소를 가진 I3C 디바이스는 해당
  주소에 대한 SMBus 읽기에도 응답하므로, 응답만으로는 디바이스가 SMBus 전용임을 증명할 수 없습니다.
  스크립트는 I3C 디바이스의 정적 주소(`--i3c-static`)를 받아, 그 밖의 모든 응답을 SMBus 전용으로
  취급합니다.
- **단계 4는 풀업이 포트 전압에 연결된 경우에만 풀업을 함께 전환합니다.** Supernova의 SDA 풀업은
  I3C 포트 전압을 따릅니다. 외부 풀업은 포트의 VTARG 핀에 연결된 경우에만 이를 따릅니다(3.3절).

### 3.2 연결

Table: Supernova I3C HV 포트와 디바이스 간 연결

| Supernova I3C HV 포트 | 디바이스 | 필수 여부 |
|---|---|---|
| SCL | SCL | 필수 |
| SDA | SDA | 필수 |
| GND | GND | 필수 |
| VTARG | 풀업 저항 또는 디바이스 I/O 전원 | 버스에 외부 풀업이 있는 경우 필수 |

### 3.3 버스 고려 사항

I3C 포트의 SCL에는 풀업이 없으며, SMBus에는 풀업이 필요합니다. SMBus 풀업은 고정 3.3 V 레일이 아니라
포트의 VTARG 핀에 연결하십시오. VTARG는 `set_voltage`를 따르므로, 단계 4에서 풀업이 버스와 함께
3.3 V에서 1.8 V로 전환됩니다. 고정 3.3 V 레일에 연결된 풀업은 단계 4 이후에도 버스를 3.3 V로 유지하며,
이는 1.8 V 디바이스가 허용하는 전압보다 높습니다.

> **주의:** 3.3 V를 견디지 못하는 디바이스는 단계 1부터 3까지 버스에 연결되어 있으면 안 됩니다.

> **주의:** 버스에는 컨트롤러가 하나만 있어야 합니다.

스크립트를 실행하는 것과 동일한 Python으로 PyPI에서 pyCosmicSDK 최신 릴리스를 설치합니다.

## 5 절차

버스에 있는 각 I3C 디바이스의 정적 주소를 지정하여 스크립트를 실행합니다. 기본값은 SMBus 3300 mV,
I3C 1800 mV이며, SETDASA로 08h부터 동적 주소를 할당합니다.

```
python smbus_to_i3c_daa.py --i3c-static 0x3A --daa setdasa
python smbus_to_i3c_daa.py --i3c-static 0x3A --daa entdaa
```

출력에는 각 단계가 표시됩니다. 6절의 벤치에서는 다음과 같습니다.

```
FW-4.6.2 controller | target FW-4.6.2
1. SMBus mode, bus at 3300 mV
2. DISEC to 7Eh: ACK, an I3C device is present
3. SMBus probe 08h-77h: 3Ah -> SMBus-only: none
4. Bus and pull-ups at 1800 mV
5. SETDASA: dynamic 08h, GETPID 0B0000000A01
```

7Eh에 ACK하는 디바이스가 없으면 단계 2 이후에, SMBus 전용 디바이스가 응답하면 단계 3 이후에 스크립트가
중지됩니다. 두 경우 모두 버스는 SMBus 전압을 유지합니다. 주소가 할당된 모든 디바이스가 PID를 반환하면
스크립트는 0으로 종료합니다.

이 시퀀스를 자체 코드에서 사용하려면 `run` 함수를 복사하십시오. 각 단계는 몇 줄에 불과하며 표 3의
호출만 사용합니다.

Table: smbus_to_i3c_daa.py 옵션

| 옵션 | 기본값 | 의미 |
|---|---|---|
| `--serial` | 임의 | 컨트롤러 Supernova의 시리얼 번호(또는 접두사) |
| `--i3c-static` | 필수 | I3C 디바이스의 정적 주소. 그 밖의 모든 SMBus 응답은 SMBus 전용으로 간주됩니다 |
| `--daa` | `setdasa` | `setdasa`는 정적 주소마다 주소 하나를 할당합니다. `entdaa`는 펌웨어가 모든 디바이스에 주소를 할당하도록 합니다 |
| `--first-dynamic` | 0x08 | SETDASA가 할당하는 첫 번째 동적 주소 |
| `--smbus-mv` | 3300 | 단계 1부터 3까지의 버스 전압 |
| `--i3c-mv` | 1800 | 버스 전압(단계 4부터) |
| `--settle-ms` | 10 | 전압 변경 후 대기 시간 |
| `--emulate-target` | 없음 | 첫 번째 `--i3c-static` 주소에서 I3C 디바이스 역할을 하는 두 번째 Supernova의 시리얼 번호 |
| `--rounds` | 1 | 시퀀스를 이 횟수만큼 실행하고 통과한 횟수를 출력합니다 |

## 7 문제 해결

Table: 문제 해결

| 증상 | 예상 원인 및 조치 |
|---|---|
| 버스에 I3C 디바이스가 있는데 단계 2가 NACK을 보고함 | 디바이스에 전원이 들어오지 않았거나 SMBus 전압이 아닙니다. `--smbus-mv`와 디바이스 전원을 확인하십시오. |
| 단계 3이 I3C 디바이스를 SMBus 전용으로 표시함 | 해당 정적 주소가 `--i3c-static`에 없습니다. 추가하십시오. |
| 단계 3에서 아무것도 찾지 못했지만 단계 5는 성공함 | 디바이스가 정적 주소에서 SMBus 읽기에 응답하지 않습니다. 이는 시퀀스에 영향을 주지 않습니다. |
| 단계 5의 GETPID가 `FW_I3C_NACK_ADDRESS`로 실패함 | 버스 전압이 아직 디바이스의 I/O 전압보다 높거나, 디바이스가 해당 DAA 방식을 지원하지 않습니다. 풀업이 VTARG에 연결되어 있는지 확인하거나 다른 `--daa`를 시도하십시오. |
| 단계 4 이후에도 버스가 3.3 V임 | 외부 풀업이 고정 3.3 V 레일에 연결되어 있습니다. VTARG에 연결하십시오(3.3절). |

## 8 약어

Table: 약어

| 용어 | 의미 |
|---|---|
| I3C | MIPI Improved Inter-Integrated Circuit |
| SMBus | System Management Bus(시스템 관리 버스) |
| CCC | I3C 공통 명령 코드(common command code) |
| DISEC | 타깃 이벤트(여기서는 핫 조인, DISHJ)를 비활성화하는 CCC |
| SETDASA | 정적 주소를 가진 디바이스에 동적 주소를 부여하는 CCC |
| ENTDAA | 모든 디바이스에 대해 동적 주소 할당을 시작하는 CCC |
| RSTDAA | 모든 동적 주소를 리셋하는 CCC |
| GETPID | 디바이스의 48비트 임시 ID를 읽는 CCC |
| PID | 임시 ID(Provisional ID) |
| BCR, DCR | I3C 버스 특성 레지스터 및 디바이스 특성 레지스터 |
| VTARG | 포트 전압으로 출력되는 Supernova I3C 포트 전원 출력 |
