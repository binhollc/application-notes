## 1 简介

有些器件上电时作为 3.3 V 的 SMBus 目标器件工作，并可以切换到 1.8 V 的 I3C。何时切换由主机决定：
主机首先确认总线上剩余的每个器件都能跟随切换，然后降低总线电压并分配动态地址。只支持 SMBus
的器件无法承受这次切换，因此主机一旦发现这样的器件，就保持在 SMBus 模式。

Supernova 的 I3C 端口在同样的两个引脚上同时支持 SMBus（传统 I2C）和 I3C，其电压由软件设置。
因此，整个流程只需一个端口和一个脚本即可运行。

### 1.1 范围

本文档涵盖：

- 流程的五个步骤，以及每个步骤背后的 pyCosmicSDK 调用
- 接线，以及总线上拉电阻必须接在何处才能随电压变化
- 一个运行该流程的脚本，地址分配使用 SETDASA 或 ENTDAA
- 在以一台 Supernova 作为 I3C 器件的测试台上的实测结果

本文档不涵盖 PCI-SIG 带外管理规范中的 SMBus 到 I3C Basic 检测流程（热加入（Hot-Join）、ARP、
SMBus 复位），这部分由 AN0014 介绍；也不涵盖 MCTP 和 NVMe-MI 消息。

## 2 系统概述

表 3 列出了各个步骤以及执行每个步骤的调用。

Table: 流程的步骤

| 步骤 | 操作 | pyCosmicSDK 调用 |
|---|---|---|
| 1 | 在 3.3 V 下以 SMBus 模式工作 | `set_voltage(voltage_mv=3300)`、`bring_up(...)`、`ccc.rstdaa()` |
| 2 | 广播一条 7Eh 命令。收到 ACK 表示总线上至少有一个 I3C 器件 | `ccc.disec_broadcast(I3cEvent.HJ)`；NACK 会引发带有 `FW_I3C_NACK_ADDRESS` 的 `I3cError` |
| 3 | 探测每个 SMBus 地址。响应且不是已知 I3C 器件的器件即为仅支持 SMBus 的器件；只要还有一个这样的器件，就保持在 SMBus 模式 | 对 08h 到 77h 执行 `legacy_i2c_read(address, 1)` |
| 4 | 将总线及其上拉电阻从 3.3 V 切换到 1.8 V | `set_voltage(voltage_mv=1800)` |
| 5 | 使用 SETDASA 或 ENTDAA 分配动态地址，然后读取每个器件的 PID | `ccc.setdasa(static=, dynamic=)` 或 `init_bus()`，然后 `ccc.getpid(address)` |

以下三点决定了该流程的形式：

- **步骤 2 是一条 CCC，而不是 SMBus 传输。** 只有 7Eh 报头以开漏方式发送，因此仅支持 SMBus
  的器件看到的是一个不属于自己的地址，并会忽略它。所用的 CCC 是带 DISHJ 的 DISEC，它同时还能防止
  I3C 器件在主机仍处于 SMBus 模式时执行热加入。
- **步骤 3 需要一份 I3C 器件静态地址的列表。** 具有静态地址的 I3C 器件也会在该地址上响应 SMBus
  读取，因此仅凭响应并不能证明某个器件仅支持 SMBus。脚本接收 I3C 器件的静态地址（`--i3c-static`），
  并将其他任何响应视为仅支持 SMBus 的器件。
- **只有当上拉电阻接在端口电压上时，步骤 4 才会使其随之切换。** Supernova 的 SDA 上拉电阻跟随
  I3C 端口电压。外部上拉电阻只有在接到端口的 VTARG 引脚时才会跟随（第 3.3 节）。

## 3 硬件设置

### 3.1 所需设备

Table: 所需设备

| 项目 |
|---|
| Binho Supernova，固件 4.6.0 或更高版本 |
| USB-C 线缆 |
| 被测器件，或用于充当被测器件的第二台 Supernova（第 6 节） |
| 接到 VTARG 的上拉电阻（如果总线上没有） |

### 3.2 连接

Table: Supernova I3C HV 端口与器件之间的连接

| Supernova I3C HV 端口 | 器件 | 是否必需 |
|---|---|---|
| SCL | SCL | 必需 |
| SDA | SDA | 必需 |
| GND | GND | 必需 |
| VTARG | 上拉电阻，或器件的 I/O 电源 | 总线有外部上拉电阻时必需 |

### 3.3 总线注意事项

I3C 端口的 SCL 上没有上拉电阻，而 SMBus 需要上拉电阻。请将 SMBus 上拉电阻接到端口的 VTARG
引脚，而不是固定的 3.3 V 电源轨。VTARG 跟随 `set_voltage`，因此步骤 4 会将上拉电阻与总线一起从
3.3 V 切换到 1.8 V。接到固定 3.3 V 电源轨的上拉电阻会在步骤 4 之后仍将总线保持在 3.3 V，
高于 1.8 V 器件所能接受的电平。

> **注意：** 不耐受 3.3 V 的器件在步骤 1 到 3 期间不得接在总线上。

> **注意：** 总线上只能有一个控制器。

## 4 软件设置

使用运行脚本的同一个 Python，从 PyPI 安装最新发布版本的 pyCosmicSDK：

```
python -m pip install --upgrade pycosmicsdk
```

使用 Mission Control 将 Supernova 更新到固件 4.6.0 或更高版本。

## 5 操作步骤

运行脚本时传入总线上每个 I3C 器件的静态地址。默认值为：SMBus 使用 3300 mV，I3C 使用 1800 mV，
并使用 SETDASA，从 08h 开始分配动态地址：

```
python smbus_to_i3c_daa.py --i3c-static 0x3A --daa setdasa
python smbus_to_i3c_daa.py --i3c-static 0x3A --daa entdaa
```

输出会标明每个步骤。在第 6 节的测试台上：

```
FW-4.6.2 controller | target FW-4.6.2
1. SMBus mode, bus at 3300 mV
2. DISEC to 7Eh: ACK, an I3C device is present
3. SMBus probe 08h-77h: 3Ah -> SMBus-only: none
4. Bus and pull-ups at 1800 mV
5. SETDASA: dynamic 08h, GETPID 0B0000000A01
```

如果没有器件对 7Eh 应答 ACK，脚本在步骤 2 之后停止；如果有仅支持 SMBus 的器件响应，脚本在步骤 3
之后停止。在这两种情况下，总线都保持在 SMBus 电压。当每个已分配地址的器件都返回了其 PID 时，
脚本以 0 退出。

要在您自己的代码中使用该流程，请复制 `run` 函数：每个步骤只有几行，并且只使用表 3 中的调用。

Table: smbus_to_i3c_daa.py 选项

| 选项 | 默认值 | 含义 |
|---|---|---|
| `--serial` | 任意 | 控制器 Supernova 的序列号（或其前缀） |
| `--i3c-static` | 必需 | I3C 器件的静态地址；其他任何 SMBus 响应都被视为仅支持 SMBus 的器件 |
| `--daa` | `setdasa` | `setdasa` 为每个静态地址分配一个地址；`entdaa` 由固件为每个器件分配地址 |
| `--first-dynamic` | 0x08 | SETDASA 分配的第一个动态地址 |
| `--smbus-mv` | 3300 | 步骤 1 到 3 的总线电压 |
| `--i3c-mv` | 1800 | 总线电压，从步骤 4 起 |
| `--settle-ms` | 10 | 电压变化后的等待时间 |
| `--emulate-target` | 无 | 第二台 Supernova 的序列号，它在第一个 `--i3c-static` 地址上充当 I3C 器件 |
| `--rounds` | 1 | 将流程运行指定次数，并打印通过的次数 |

## 7 故障排除

Table: 故障排除

| 现象 | 可能原因及处理方法 |
|---|---|
| 总线上有 I3C 器件，但步骤 2 报告 NACK | 器件未上电，或未处于 SMBus 电压。请检查 `--smbus-mv` 和器件电源。 |
| 步骤 3 将 I3C 器件列为仅支持 SMBus 的器件 | `--i3c-static` 中缺少其静态地址。请添加该地址。 |
| 步骤 3 未发现任何器件，但步骤 5 仍然成功 | 器件不在其静态地址上响应 SMBus 读取。这不影响该流程。 |
| 步骤 5 的 GETPID 因 `FW_I3C_NACK_ADDRESS` 失败 | 总线电压仍高于器件的 I/O 电压，或器件不支持所用的 DAA 方法。请检查上拉电阻是否接到 VTARG，或尝试另一个 `--daa`。 |
| 步骤 4 之后总线仍为 3.3 V | 外部上拉电阻接在固定的 3.3 V 电源轨上。请将其接到 VTARG（第 3.3 节）。 |

## 8 缩略语

Table: 缩略语

| 术语 | 含义 |
|---|---|
| I3C | MIPI Improved Inter-Integrated Circuit |
| SMBus | System Management Bus（系统管理总线） |
| CCC | I3C 通用命令代码（common command code） |
| DISEC | 禁用目标器件事件的 CCC，此处为热加入（DISHJ） |
| SETDASA | 为具有静态地址的器件分配动态地址的 CCC |
| ENTDAA | 为每个器件启动动态地址分配的 CCC |
| RSTDAA | 复位所有动态地址的 CCC |
| GETPID | 读取器件 48 位临时 ID 的 CCC |
| PID | 临时 ID（Provisional ID） |
| BCR、DCR | I3C 总线特性寄存器和器件特性寄存器 |
| VTARG | Supernova I3C 端口的电源输出，电压等于端口电压 |
