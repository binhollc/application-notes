## 1 はじめに

一部のデバイスは 3.3 V の SMBus ターゲットとして起動し、1.8 V の I3C に移行できます。移行のタイミングは
ホストが決定します。ホストはまず、バス上に残るすべてのデバイスが移行に追従できることを確認し、その後
バス電圧を下げてダイナミックアドレスを割り当てます。SMBus しか使えないデバイスはこの移行に耐えられない
ため、そのようなデバイスが見つかった場合、ホストは SMBus モードのままにします。

Supernova の I3C ポートは、同じ 2 本のピンで SMBus（レガシー I2C）と I3C の両方を扱え、その電圧は
ソフトウェアから設定します。そのため、一連の手順全体を 1 つのポートと 1 つのスクリプトで実行できます。

### 1.1 対象範囲

本書では以下を扱います。

- 一連の手順の 5 つのステップと、各ステップの背後にある pyCosmicSDK の呼び出し
- 配線、およびバスのプルアップが電圧変更に追従するための接続先
- SETDASA または ENTDAA をアドレス割り当てに使用して一連の手順を実行するスクリプト
- Supernova を I3C デバイスとして使用したベンチでの測定結果

PCI-SIG のアウトオブバンド管理仕様における SMBus から I3C Basic への検出フロー（ホットジョイン
（Hot-Join）、ARP、SMBus リセット）は AN0014 で扱うため本書では扱いません。また、MCTP および NVMe-MI
のメッセージも扱いません。

## 2 システム概要

表 3 に、各ステップとそれを実行する呼び出しを示します。

Table: 一連の手順のステップ

| ステップ | 動作 | pyCosmicSDK の呼び出し |
|---|---|---|
| 1 | 3.3 V の SMBus モードで動作する | `set_voltage(voltage_mv=3300)`、`bring_up(...)`、`ccc.rstdaa()` |
| 2 | 7Eh コマンドをブロードキャストする。ACK は、バス上に少なくとも 1 つの I3C デバイスがあることを意味する | `ccc.disec_broadcast(I3cEvent.HJ)`。NACK の場合は `FW_I3C_NACK_ADDRESS` を伴う `I3cError` が発生する |
| 3 | すべての SMBus アドレスをプローブする。応答し、かつ既知の I3C デバイスではないデバイスは SMBus 専用である。そのようなデバイスが残っている場合は SMBus モードのままにする | 08h から 77h に対して `legacy_i2c_read(address, 1)` |
| 4 | バスとそのプルアップを 3.3 V から 1.8 V に移行する | `set_voltage(voltage_mv=1800)` |
| 5 | SETDASA または ENTDAA でダイナミックアドレスを割り当て、各デバイスの PID を読み出す | `ccc.setdasa(static=, dynamic=)` または `init_bus()`、その後 `ccc.getpid(address)` |

一連の手順は、次の 3 つの事実に基づいています。

- **ステップ 2 は SMBus 転送ではなく CCC です。** オープンドレインで送信されるのは 7Eh ヘッダのみである
  ため、SMBus 専用デバイスには自分のものではないアドレスが見え、それを無視します。使用する CCC は DISHJ
  を指定した DISEC で、ホストがまだ SMBus モードにある間に I3C デバイスがホットジョインすることも防ぎます。
- **ステップ 3 には I3C デバイスのスタティックアドレスのリストが必要です。** スタティックアドレスを持つ
  I3C デバイスは、そのアドレスへの SMBus 読み出しにも応答するため、応答があるだけではそのデバイスが
  SMBus 専用であることの証明になりません。スクリプトは I3C デバイスのスタティックアドレス
  （`--i3c-static`）を受け取り、それ以外の応答をすべて SMBus 専用として扱います。
- **ステップ 4 でプルアップが移行するのは、プルアップがポート電圧から供給されている場合のみです。**
  Supernova の SDA プルアップは I3C ポート電圧に追従します。外部プルアップが追従するのは、ポートの VTARG
  ピンに接続されている場合のみです（3.3 節）。

### 3.3 バスに関する考慮事項

I3C ポートの SCL にはプルアップがなく、SMBus にはプルアップが必要です。SMBus のプルアップは、固定の
3.3 V レールではなく、ポートの VTARG ピンに接続してください。VTARG は `set_voltage` に追従するため、
ステップ 4 でプルアップはバスとともに 3.3 V から 1.8 V に移行します。固定の 3.3 V レールに接続した
プルアップでは、ステップ 4 の後もバスが 3.3 V に保たれ、1.8 V デバイスが許容する電圧を超えてしまいます。

> **注意：** 3.3 V トレラントでないデバイスは、ステップ 1 から 3 の間、バス上に接続しないでください。

> **注意：** バス上のコントローラは 1 つだけにしてください。

## 4 ソフトウェアのセットアップ

スクリプトを実行するのと同じ Python で、PyPI から pyCosmicSDK の最新リリースをインストールします。

```
python -m pip install --upgrade pycosmicsdk
```

Mission Control で Supernova をファームウェア 4.6.0 以降に更新します。

## 5 手順

バス上の各 I3C デバイスのスタティックアドレスを指定してスクリプトを実行します。デフォルトは、SMBus が
3300 mV、I3C が 1800 mV で、SETDASA により 08h からダイナミックアドレスを割り当てます。

```
python smbus_to_i3c_daa.py --i3c-static 0x3A --daa setdasa
python smbus_to_i3c_daa.py --i3c-static 0x3A --daa entdaa
```

出力には各ステップが示されます。6 章のベンチでは次のとおりです。

```
FW-4.6.2 controller | target FW-4.6.2
1. SMBus mode, bus at 3300 mV
2. DISEC to 7Eh: ACK, an I3C device is present
3. SMBus probe 08h-77h: 3Ah -> SMBus-only: none
4. Bus and pull-ups at 1800 mV
5. SETDASA: dynamic 08h, GETPID 0B0000000A01
```

7Eh に ACK するデバイスがない場合はステップ 2 の後で、SMBus 専用デバイスが応答した場合はステップ 3 の後で
スクリプトは停止します。どちらの場合も、バスは SMBus の電圧のままです。アドレスを割り当てたすべての
デバイスが PID を返した場合、スクリプトは 0 で終了します。

一連の手順を独自のコードで使用するには、`run` 関数をコピーしてください。各ステップは数行で、表 3 の
呼び出しのみを使用します。

Table: smbus_to_i3c_daa.py のオプション

| オプション | デフォルト | 意味 |
|---|---|---|
| `--serial` | 任意 | コントローラ Supernova のシリアル番号（またはその先頭部分） |
| `--i3c-static` | 必須 | I3C デバイスのスタティックアドレス。それ以外の SMBus 応答はすべて SMBus 専用として扱われる |
| `--daa` | `setdasa` | `setdasa` はスタティックアドレスごとに 1 つのアドレスを割り当てる。`entdaa` はファームウェアにすべてのデバイスへの割り当てを任せる |
| `--first-dynamic` | 0x08 | SETDASA が割り当てる最初のダイナミックアドレス |
| `--smbus-mv` | 3300 | ステップ 1 から 3 のバス電圧 |
| `--i3c-mv` | 1800 | バス電圧（ステップ 4 以降） |
| `--settle-ms` | 10 | 電圧変更後の待ち時間 |
| `--emulate-target` | なし | 最初の `--i3c-static` アドレスで I3C デバイスの役割を果たす 2 台目の Supernova のシリアル番号 |
| `--rounds` | 1 | 一連の手順をこの回数だけ実行し、成功した回数を表示する |

## 7 トラブルシューティング

Table: トラブルシューティング

| 症状 | 考えられる原因と対処 |
|---|---|
| バス上に I3C デバイスがあるのに、ステップ 2 が NACK を報告する | デバイスに電源が入っていないか、SMBus の電圧になっていません。`--smbus-mv` とデバイスの電源を確認してください。 |
| ステップ 3 が I3C デバイスを SMBus 専用として表示する | そのスタティックアドレスが `--i3c-static` に含まれていません。追加してください。 |
| ステップ 3 で何も見つからないが、ステップ 5 は成功する | デバイスがスタティックアドレスで SMBus 読み出しに応答しません。一連の手順には影響しません。 |
| ステップ 5 の GETPID が `FW_I3C_NACK_ADDRESS` で失敗する | バスがまだデバイスの I/O 電圧より高いか、デバイスがその DAA 方式をサポートしていません。プルアップが VTARG に接続されていることを確認するか、もう一方の `--daa` を試してください。 |
| ステップ 4 の後もバスが 3.3 V のまま | 外部プルアップが固定の 3.3 V レールに接続されています。VTARG に接続してください（3.3 節）。 |

## 8 略語

Table: 略語

| 用語 | 意味 |
|---|---|
| I3C | MIPI Improved Inter-Integrated Circuit |
| SMBus | System Management Bus（システムマネジメントバス） |
| CCC | I3C 共通コマンドコード（common command code） |
| DISEC | ターゲットイベント（ここではホットジョイン、DISHJ）を無効にする CCC |
| SETDASA | スタティックアドレスを持つデバイスにダイナミックアドレスを与える CCC |
| ENTDAA | すべてのデバイスに対してダイナミックアドレス割り当てを開始する CCC |
| RSTDAA | すべてのダイナミックアドレスをリセットする CCC |
| GETPID | デバイスの 48 ビットのプロビジョナル ID を読み出す CCC |
| PID | プロビジョナル ID（Provisional ID） |
| BCR、DCR | I3C のバス特性レジスタおよびデバイス特性レジスタ |
| VTARG | ポート電圧で出力される Supernova I3C ポートの電源出力 |
