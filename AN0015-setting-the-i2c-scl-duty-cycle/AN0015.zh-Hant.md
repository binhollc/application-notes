## 1 簡介

I2C 控制器會為每個 SCL 週期選擇高電位時間與低電位時間。I2C 規範為兩者都訂有最小值（tHIGH 與
tLOW），多數控制器會自行選擇分配方式。這在目標裝置對此不敏感、測試計畫也未要求特定分配時並無問題；
但測試計畫可能會要求例如 30:70 的時脈，以確認目標裝置在高電位階段較短時仍能正確取樣，或要求 40:60
的時脈，以符合目標裝置將出貨之系統的時序。

在此之前，Binho 主機轉接器都是自行選擇分配方式。在 100 kHz 下，預設約為 46 百分比高電位；在
400 kHz 下，約為 40 百分比。過去無法要求其他比例。主機轉接器韌體 4.6.0 與 pyCosmicSDK 1.6.0
新增了一個用來設定它的呼叫。

### 1.1 範圍

本文件涵蓋：

- `I2cController.set_duty_cycle` 做了什麼，以及它不改變什麼
- 韌體接受的比例，以及對其拒絕的比例所回應的內容
- 為什麼設定比例也會讓頻率變得精確
- 一個套用比例、產生可供量測的傳輸並印出主機轉接器回報值的腳本
- 在 100 kHz 與 400 kHz 下於線路上量測到的分配

本文件不涵蓋 20 至 80 百分比以外的比例、Supernova I3C 連接埠上的工作週期控制，也不涵蓋 SPI。SPI
時脈時序屬於另一項韌體變更。

## 2 系統概觀

`set_duty_cycle(high_pct)` 設定每個 SCL 週期中時脈保持高電位的比例。依韌體的實作方式，可推得以下
三點：

- **頻率不變。** 匯流排維持傳給 `bring_up` 或 `configure` 的頻率。只有分配會改變。
- **頻率變得精確。** 未設定比例時，主機轉接器會選擇其可達到的最接近除頻值，且可能捨入到高於要求值：
  550 kHz 實際以 600.6 kHz 執行。設定比例後，韌體會將 I2C 周邊切換到更精細的時脈，因此頻率絕不會
  高於要求值，且最多低 0.29 百分比。同樣的 550 kHz 實際以 549.8 kHz 執行。
- **比例會持續保留。** 之後的 `configure` 會保留比例，並在新的頻率下套用。`set_duty_cycle(0)`
  或重新執行 `initialize` 會回到預設時序。

此呼叫以 `I2cDutyCycle` 傳回實際生效的設定，包含兩個欄位：

Table: I2cDutyCycle 的欄位

| 欄位 | 意義 |
|---|---|
| `frequency_hz` | 設定比例時，為線路上的頻率。`high_pct` 為 0 時，為要求的頻率，預設時序可能會將其捨入 |
| `high_pct` | 實際生效的比例，以百分比表示；0 為預設時序 |

韌體不會依 I2C 規範限制比例。100 kHz 下 30 百分比的時脈，其 tHIGH 為 3.0 us，低於 Standard-mode
的 4.0 us 最小值。這是刻意的：餘裕測試正需要超出規範的時序。在產品中使用某個比例之前，請先依規範
檢查。

## 3 硬體設定

### 3.1 所需設備

Table: 所需設備

| 項目 |
|---|
| Binho Supernova 或 Pulsar，韌體 4.6.0 或更新版本 |
| USB-C 傳輸線 |
| 一個 I2C 目標裝置；若目的只是量測 SCL，則不需要 |
| 接在 SCL 上的示波器或邏輯分析儀，用來量測結果 |

### 3.2 連接

Table: I2C 連接埠的連接

| 主機轉接器 | 目標裝置或儀器 | 必要性 |
|---|---|---|
| SCL | 目標裝置 SCL、儀器探棒 | 必要 |
| SDA | 目標裝置 SDA | 有目標裝置時必要 |
| GND | 目標裝置與儀器接地 | 必要 |
| 3.3 V | 目標裝置電源 | 選用 |

### 3.3 匯流排注意事項

主機轉接器從偵測到 SCL 為高電位的時刻開始計算 tHIGH。因此，緩慢的上升緣會拉長週期：使用 2.2 kOhm
上拉電阻時，1 MHz 時脈實際約以 905 kHz 執行。在 1 MHz 下請使用 470 Ohm 或更強的上拉電阻。在
100 kHz 與 400 kHz 下，1 kOhm 至 2.2 kOhm 即已足夠。

## 4 軟體設定

安裝 pyCosmicSDK（最新版本）：

```
pip install --upgrade pycosmicsdk
```

腳本 `i2c_duty_cycle.py` 位於資產壓縮檔中，不需要其他任何東西。

## 5 工作週期呼叫

單獨列出的呼叫：

```python
import pycosmicsdk as p

dev = p.Device.open(model=p.DeviceModel.SUPERNOVA)
bus = dev.i2c()
bus.set_voltage(voltage_mv=3300)
bus.bring_up(frequency_hz=400_000, pull_up=p.I2cPullUp.KOHM_1_0)
print(bus.set_duty_cycle(high_pct=40))
# I2cDutyCycle(frequency_hz=400000, high_pct=40)
```

Table: set_duty_cycle 接受的值

| `high_pct` | 結果 |
|---|---|
| 0 | 預設時序，與韌體 4.5.1 相同 |
| 20, 30, 40, 50, 60, 70, 80 | 每個週期中該比例為高電位；頻率精確 |
| 其他任何值 | `FirmwareError`，狀態為 `FW_INVALID_PARAMETER`；保留實際生效的比例 |

在韌體 4.5.1 及更早版本上，此呼叫會引發狀態為 `FW_UNSUPPORTED_COMMAND` 的 `FirmwareError`，
且匯流排仍可正常運作。

## 6 程序

1. 連接主機轉接器，若有使用儀器，將其接在 SCL 上。

2. 詢問主機轉接器在相關頻率下對每個比例回報的值。每個頻率以 `configure` 套用，接著依序套用每個
   比例，最後恢復預設時序：

```

request   100 kHz  ->    100000 Hz  40 % high
request   100 kHz  ->    100000 Hz  50 % high
request   100 kHz  ->    100000 Hz  60 % high
request   100 kHz  ->    100000 Hz  70 % high
request   100 kHz  ->    100000 Hz  80 % high
request   400 kHz  ->    400000 Hz  default
request   400 kHz  ->    400000 Hz  20 % high
request   400 kHz  ->    400000 Hz  30 % high
request   400 kHz  ->    400000 Hz  40 % high
request   400 kHz  ->    400000 Hz  50 % high
request   400 kHz  ->    400000 Hz  60 % high
request   400 kHz  ->    400000 Hz  70 % high
request   400 kHz  ->    400000 Hz  80 % high
request  1000 kHz  ->   1000000 Hz  default
request  1000 kHz  ->    999024 Hz  20 % high
request  1000 kHz  ->    999024 Hz  30 % high
request  1000 kHz  ->    999024 Hz  40 % high
request  1000 kHz  ->    999024 Hz  50 % high
request  1000 kHz  ->    999024 Hz  60 % high
request  1000 kHz  ->    999024 Hz  70 % high
request  1000 kHz  ->    999024 Hz  80 % high
```

   在 1 MHz 下，精確頻率為 999024 Hz，比要求值低 0.1 百分比。`default` 列回報的是要求值，而非
   線路上的實際值；第 8.2 節列出兩者的差異。

3. 套用一個比例。使用 `--traffic` 時，腳本會讓 SCL 持續運作該秒數，以便儀器擷取：

```
$ python i2c_duty_cycle.py --model supernova --pull-up KOHM_1_0 set --khz 100 --high 30
SUPERNOVA FW-4.5.1-80cbb484  I2C 3300 mV  pull-up KOHM_1_0
request   100 kHz  ->    100000 Hz  30 % high
```

4. 不在接受範圍內的比例會被拒絕，實際生效的比例維持不變：

```
$ python i2c_duty_cycle.py --model supernova --pull-up KOHM_1_0 set --khz 100 --high 35
error: i2c_set_duty_cycle: FW_INVALID_PARAMETER: At least one of the parameters of the command is not valid.
SUPERNOVA FW-4.5.1-80cbb484  I2C 3300 mV  pull-up KOHM_1_0
```

5. 在預設時序會捨入的頻率下，比較設定比例與預設時序：

```
$ python i2c_duty_cycle.py --model supernova --pull-up KOHM_1_0 set --khz 550 --high 50
SUPERNOVA FW-4.5.1-80cbb484  I2C 3300 mV  pull-up KOHM_1_0
request   550 kHz  ->    549798 Hz  50 % high
$ python i2c_duty_cycle.py --model supernova --pull-up KOHM_1_0 set --khz 550 --high 0
SUPERNOVA FW-4.5.1-80cbb484  I2C 3300 mV  pull-up KOHM_1_0
request   550 kHz  ->    550000 Hz  default
```

   第二行回報 550000 Hz，因為它只是回傳要求值。在線路上，預設時序實際以 600.6 kHz 執行
   （第 8.2 節）。

## 7 參考

Table: i2c_duty_cycle.py 選項

| 選項 | 預設值 | 意義 |
|---|---|---|
| `--model` | 任何 | `supernova` 或 `pulsar`，用於兩者都連接時 |
| `--serial` | 任何 | 主機轉接器序號 |
| `--voltage-mv` | 3300 | 匯流排電壓 |
| `--pull-up` | `KOHM_2_2` | 板載上拉電阻，任何 `I2cPullUp` 名稱 |

Table: i2c_duty_cycle.py 命令

| 命令 | 選項 | 動作 |
|---|---|---|
| `set` | `--khz`、`--high`、`--traffic`、`--address` | 套用一個比例；使用 `--traffic` 時，在該秒數內從 `--address` 讀取 |
| `table` | `--khz`（一個或多個） | 印出 0 以及 20 至 80 百分比所回報的頻率與比例，然後恢復預設時序 |

傳輸預設從位址 0x50 讀取。若該位址沒有目標裝置，每次讀取為一個位址位元組加一個 NACK，仍會產生九個
SCL 週期。

## 8 量測結果

### 8.1 測試組態

Table: 測試組態

| 項目 | 值 |
|---|---|
| 主機轉接器 | Binho Supernova，硬體版本 C，韌體 `FW-4.5.1-80cbb484`（4.6.0 預發行版） |
| 主機軟體 | pyCosmicSDK 1.6.0 預發行版，`integration/1.6.0` 於 `baacfdba` |
| 匯流排 | I2C 連接埠，3.3 V，1 kOhm 板載上拉電阻，無目標裝置 |
| 傳輸 | `set --traffic 10`，每次擷取約 4800 筆傳輸 |
| 儀器 | Acute TravelBus 邏輯分析儀接在 SCL 上，800 MS/s，臨界值 1.6 V |
| 擷取 | 每個點 3 次，電源重啟後每個點再 1 次；每次約 15000 個 SCL 週期 |

### 8.2 結果

數值為中位數。比例欄為單次擷取中 tHIGH 佔週期比例的中位數；p1 至 p99 欄為其分布範圍。每個點的四次
擷取彼此一致，差異在 0.1 百分比以內。

Table: 線路上量測的 SCL 時序

| 要求值 | 比例 | 頻率 | 高電位 | tHIGH | tLOW | 高電位，p1 至 p99 |
|---|---|---|---|---|---|---|
| 100 kHz | 預設 | 100.0 kHz | 46.4 % | 4645 ns | 5360 ns | 46.1 至 46.9 % |
| 100 kHz | 30 | 100.0 kHz | 29.7 % | 2975 ns | 7030 ns | 29.4 至 30.1 % |
| 100 kHz | 40 | 100.0 kHz | 39.9 % | 3990 ns | 6015 ns | 39.2 至 40.1 % |
| 100 kHz | 50 | 100.0 kHz | 49.6 % | 4965 ns | 5035 ns | 49.2 至 50.2 % |
| 400 kHz | 預設 | 400.0 kHz | 39.6 % | 990 ns | 1510 ns | 38.6 至 41.1 % |
| 400 kHz | 30 | 400.0 kHz | 28.0 % | 700 ns | 1800 ns | 27.2 至 30.7 % |
| 400 kHz | 40 | 400.0 kHz | 39.5 % | 990 ns | 1515 ns | 38.8 至 40.7 % |
| 400 kHz | 50 | 400.0 kHz | 48.8 % | 1220 ns | 1280 ns | 48.2 至 50.7 % |

在 400 kHz 下，量測到的高電位比例比設定比例低 0.5 至 2 個百分點。這是上升緣造成的：分析儀只在 SCL
越過 1.6 V 後才判定為高電位，而在 400 kHz 下，此延遲佔週期的比例較大。

另有兩個點是在韌體驗證期間，於相同變更的較早建置上量測，並非使用上述組態：

- 1 MHz，使用 470 Ohm 上拉電阻，Supernova：比例 30、40 與 50 分別得到 1000.0 kHz，29.5、37.0 與
  50.5 百分比。
- 550 kHz：在兩種主機轉接器以及 4.5.1 正式版上，預設時序皆以 600.6 kHz、50.2 百分比高電位執行。
  比例 50 則以 551.0 kHz 執行。

20、60、70 與 80 百分比的比例是透過主機轉接器的回報值檢查（第 6 節，步驟 2），未在線路上量測。

## 9 疑難排解

Table: 疑難排解

| 症狀 | 可能原因與處置 |
|---|---|
| `FW_UNSUPPORTED_COMMAND` | 韌體 4.5.1 或更早版本。請將主機轉接器更新至 4.6.0 或更新版本。 |
| `FW_INVALID_PARAMETER` | 比例不是 0，也不是 20 至 80 之間以 10 為級距的值。先前的比例仍然有效。 |
| `FW_INTERFACE_NOT_INITIALIZED` | I2C 匯流排未以控制器身分啟動。請先呼叫 `bring_up`。 |
| 在 1 MHz 下量測到的頻率低於要求值 | 上升緣太慢。請使用 470 Ohm 或更強的上拉電阻（第 3.3 節）。 |
| 腳本重新啟動後比例回到預設值 | `initialize` 會恢復預設時序。每次以 `bring_up` 初始化匯流排後，都請呼叫 `set_duty_cycle`。 |
| `table` 出現 `CapabilityError` | `configure` 需要硬體版本 C 的 Supernova。請改為每個頻率各執行一次 `set`。 |
