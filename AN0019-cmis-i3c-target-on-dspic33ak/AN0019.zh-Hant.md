## 1 簡介

CMIS 模組提供一個 256 位元組的視窗，由低端記憶區（Lower Memory）加上高端記憶區（Upper Memory）的一個
128 位元組頁組成，頁由 `00h:127` 處的頁選擇位元組選定。透過 I2C，主機先寫入位元組位址，然後以重複 START 進行讀取。
正在為 CMIS 定義的 I3C 管理介面保留了這種存取方式，因此以 I3C 目標裝置周邊建構的模組必須回應這樣一個讀取：
其位元組位址在同一次傳輸中僅早幾個位元時間到達。

如果周邊在每個位元組到達時就將其交給韌體，這很容易做到。而 dsPIC33AK256MPS306 的 I3C 周邊則是以命令與回應為基礎：
接收到的傳輸只以回應的形式回報一次，讀取由一個傳送命令回應，而該命令必須在讀取標頭到達時就已經有效。
本應用筆記探討的就是如何讓這兩者銜接起來。

### 1.1 範圍

- dsPIC33AK 上的 CMIS 暫存器模型：分頁、第 8.2.15 節的不支援頁覆寫、附錄 B.1.2 規定的 128 位元組區段內環繞，
  以及攜帶 Flags Summary 位元組 `00h:4` 的 IBI。
- 在 2.5 MHz 推挽模式下回應寫入 + Sr + 讀取（組合讀取）以及寫入、STOP、讀取（分離讀取）。
- 動態位址分配（DAA）、RSTDAA 和 Direct GET CCC。
- 一個從 Supernova 執行本筆記中所有檢查的主機指令碼。

不涵蓋：CDB、韌體下載、HDR 模式，以及 CMIS 控制暫存器在模組端的意義。除頁選擇與主機寫入的位元組外，
暫存器映像是靜態的。

## 2 系統概觀

Supernova 是 I3C 控制器，也是匯流排上唯一的控制器。dsPIC33AK 是目標裝置，靜態位址為 `0x50`，即 CMIS
模組位址。控制器透過 ENTDAA 為其分配動態位址（測試台分配 `0x08`），然後以 SDR 對其進行讀寫。

決定韌體設計的唯一事實是：組合讀取的位元組位址何時變得可見。在關閉 I3C 中斷的情況下，以 100 MHz 計時器為基準
輪詢周邊，並與邏輯分析儀對齊，量測結果如下：

Table: 2.5 MHz 推挽下的組合讀取，自 START 起算的時間

| 事件 | 時間 |
|---|---|
| 位元組位址的 T 位元 | 22.3 µs |
| 位元組位址進入接收 FIFO | 23.8 µs |
| 重複 START | 24.1 µs |
| 讀取標頭的 ACK 時槽 | ~27.4 µs |
| 寫入的回應中斷 | ACK 時槽之後 |

由寫入的回應中斷備妥（arm）的傳送命令總是太遲，目標裝置會對讀取回以 NACK。位元組位址本身在 ACK 時槽之前
3.6 µs 即可取得，而備妥一個命令需要 1.15 到 1.26 µs。因此韌體由接收 DMA 進行備妥：將接收到的字組搬移到 RAM
的通道每個字組產生一次中斷，其優先順序高於 I3C 中斷，該中斷依據第一個位元組備妥傳送命令。

其餘一切都源自該周邊及其 MCC Melody 驅動程式的三項特性：

- 一個傳送命令回應一次讀取。韌體備妥從位元組位址到區段結尾的 128 位元組資料串；控制器會提前結束讀取。
- 傳送緩衝區可容納 8 個字組（32 位元組）。資料串的其餘部分由主迴圈供給。任何使主迴圈離開的時間超過傳送 32 位元組
  所需時間（約 115 µs）的動作，都會使讀取在 32 位元組處被截斷。
- 重新備妥接收會重設接收 FIFO，同時也會捨棄已備妥的傳送命令。接收僅在讀取之後才重新備妥。

## 5 目標裝置韌體設計

### 5.1 暫存器模型

低端記憶區與高端記憶區頁 `00h` 取自 CMIS 5.3 附錄 C 的範例映像。`00h:127` 處的頁選擇接受 `00h` 和 `01h`；
任何其他值都會被替換為 `00h`（第 8.2.15 節）。每個區段首尾相接儲存兩次，另加偏移一到三個位元組的副本，
因此從任何位元組位址開始的 128 位元組資料串都是一個對齊的緩衝區，區段內的 B.1.2 環繞不需要任何程式碼。

### 5.2 識別資訊

Table: 控制器看到的識別資訊

| 項目 | 值 |
|---|---|
| 靜態位址 | `0x50` |
| PID | `02 36 43 4D 49 53`（MIPI 製造商 `0x11B`，元件 `"CMIS"`） |
| BCR | `0x17`：支援 IBI，IBI 攜帶一個位元組，有最大資料速率限制 |
| DCR | `0x00` |

### 5.3 備妥讀取

1. 接收 DMA 通道將每個接收到的字組搬移到 `rxbuf`，其完成中斷已啟用，優先順序為 5，高於優先順序為 4 的 I3C 中斷。
2. 在寫入的第一個字組到達時，DMA 中斷將 `rxbuf[0]` 作為位元組位址，並備妥從該位址開始之資料串的傳送命令。
3. 當寫入的回應到達且其中只攜帶了位址時，命令保持備妥狀態，接收在讀取完成後重新備妥。
4. 當寫入攜帶了資料時，透過重設延伸傳送緩衝區來取消該命令，並立即重新備妥接收。
5. 如果讀取標頭到達時仍未找到已備妥的命令，周邊會發出讀取請求。韌體捨棄任何遲到備妥的命令，並透過
   `I3C1_Target_ReceiveCancel()` 重新備妥接收，因為在這種情況下寫入的回應永遠不會到來。

### 5.4 供給長讀取

傳送緩衝區預先填入 8 個字組。`I3C1_Target_TxRefill()` 從主迴圈供給其餘部分，在其執行的少數指令期間遮罩 I3C
與 DMA 中斷。開發調試韌體的 UART 狀態列預設為關閉：其在 9600 鮑率下的阻塞式 `printf` 每秒佔用主迴圈約 110 ms，
使 128 位元組的讀取在 32 位元組處被截斷。

### 5.5 事件

在 IBI 啟用期間，IBI 每秒發出一次，以 `00h:4` 作為其必要的資料位元組。周邊重設後 IBI 處於啟用狀態，這符合
I3C Basic 的規定，而且周邊不會保留寫入該啟用位元的 0：DISEC 才是關閉 IBI 的方法。

### 5.6 對 Melody 驅動程式的修改

Table: `mcc/` 中的本地修改，以 `binho:` 標記

| 修改 | 原因 |
|---|---|
| `BufferTransmit` 預先填入 8 個字組；`I3C1_Target_TxRefill()` 供給其餘部分 | 超過 8 個字組時，DMA 路徑將第 7 個字組寫了兩次且不再繼續，因此命令遭到拒絕 |
| `I3C1_Target_ReceiveCancel()` | 在寫入 + Sr + 被 NACK 的讀取標頭之後，寫入不會有回應；驅動程式一直將其接收標記為進行中，並拒絕之後的每一次接收 |
| 在完成回呼之前清除 `rxInProgress` | 使回呼能夠重新備妥接收 |
| 靜態位址 `0x50` | CMIS 模組位址 |

## 6 操作程序

**步驟 1**：在韌體資料夾中建置目標裝置韌體並燒錄：

```
make flash
```

建置以 MPLAB IPE 輸出的 `Program Succeeded.` 結束。

**步驟 2**：依表 4 將 Supernova I3C 連接埠連接到 DIM。

**步驟 3**：以寫入 + Sr + 讀取方式讀取 128 位元組，共 60 次：

```
python cmis_target_check.py reads --length 128 --count 60
```

```
init bus: FW_I3C_BUS_INIT_NACK_RSTDAA
target DA 0x08, PID 02 36 43 4d 49 53
............................................................
reads 60/60  (combined, 128 B, IBI off)
```

`init bus` 這一行表示重設後的第一次 RSTDAA 被 NACK（第 8.3 節）；指令碼會再次初始化。

**步驟 4**：在啟用 IBI 的情況下執行相同動作（讀取之前送出 ENEC）：

```
python cmis_target_check.py reads --length 128 --count 300 --ibi
```

```
reads 299/300  (combined, 128 B, IBI on)
```

點列中的 `F` 表示發生錯誤的讀取，`B` 表示傳回錯誤資料的讀取。

**步驟 5**：資料寫入與讀取混合：每一輪寫入 `7Fh=00h` 和 `7Eh=00h`，然後讀取 `7Fh`（1 位元組）和 `80h`
（16 位元組），並與映像進行比對：

```
python cmis_target_check.py mixed --count 60
```

```
rounds 60/60
```

**步驟 6**：位址重設與重新分配：

```
python cmis_target_check.py daa --cycles 10
```

```
0: RSTDAA SUCCESS, GETSTATUS at old DA FW_I3C_NACK_ADDRESS, read after ENTDAA ok
...
cycles 10/10
```

**步驟 7**：識別資訊與 Direct GET CCC：

```
python cmis_target_check.py ccc --getstatus 100
```

```
GETBCR   SUCCESS                17
GETDCR   SUCCESS                00
GETPID   SUCCESS                02 36 43 4d 49 53
GETMXDS  SUCCESS                00 00 00 00 01
GETMRL   FW_I3C_NACK_ADDRESS    
GETMWL   SUCCESS                ff
GETSTATUS 100/100  {'SUCCESS': 100}
```

Direct GET 可能因 `7Eh` 標頭被 NACK 而失敗（第 8.3 節）；此處 GETMRL 即失敗了。請再執行一次。

## 7 參考

Table: `cmis_target_check.py` 命令

| 命令 | 功能 |
|---|---|
| `reads --length N --count N [--split] [--ibi]` | 依序在 `00h`、`10h`、`7Ch`、`80h`、`A0h`、`FCh` 處讀取並與映像比對。除非指定 `--split`，否則為組合讀取；`--ibi` 先送出 ENEC，否則送出 DISEC |
| `mixed --count N` | 向 `7Fh` 和 `7Eh` 寫入資料，然後對 `7Fh` 和 `80h` 進行組合讀取並驗證 |
| `ccc [--getstatus N]` | GETBCR、GETDCR、GETPID、GETMXDS、GETMRL、GETMWL，然後執行 GETSTATUS N 次 |
| `daa --cycles N` | RSTDAA，檢查舊位址是否 NACK，ENTDAA，檢查一次讀取 |
| `i2c` | 在任何位址分配之前，以 I2C 模式在 `0x50` 處讀取 `00h:0-3` 和 `00h:46-48` |

通用選項：`--serial`、`--push-pull`（預設 `PUSH_PULL_2_5_MHZ_DC_25`）、`--voltage-mv`（預設 3300）、
`--image`（預設為指令碼旁的 `cmis_image.h`）。每個命令都以 RSTDAA 和 ENTDAA 開始，並依 PID 中的 `"CMIS"`
找到目標裝置。

### 8.3 主機應預期的行為

- **目標裝置重設後的第一次傳輸會被 NACK**。在 5 次重設的每一次之後，第一個 `7Eh` 標頭都被 NACK，第二個被 ACK。
  DS70005539 第 24.4.5 節描述該模組只有在偵測到 SCL 時脈後才離開重設。只探測一次並將 NACK 視為
  「無 I3C 目標裝置」的主機將會漏掉此模組；請重試探測。
- **部分 Direct GET CCC 會因 `7Eh` 被 NACK 而失敗**。在一個工作階段中，Direct GET 之後的 `7Eh` 標頭約每 7 個中有
  1 個被 NACK（1200 次 GET 中有 173 次失敗，全部 173 次在線路上都可見為 `7E/W NACK`）；在另一個工作階段中，
  500 次中 500 次通過。私有讀取不受影響。請重試因 NACK 而失敗的 GET。
- **GETMRL 回報 255，且 SETMRL 不會生效**。韌體設定為 128；周邊自行以 255 回應 GETMRL。執行 SETMRL 16 之後，
  32 位元組的讀取仍傳回 32 位元組。

### 8.4 位址分配之前的 I2C 讀取

在 ENTDAA 之前，目標裝置在 `0x50` 處回應 I2C。從 Supernova 的 I2C 連接埠（一個一般 I2C 控制器，3.3 V 下使用
2.2 kOhm 上拉電阻）進行讀取，每次執行前都燒錄目標裝置，在 `00h`、`10h`、`7Ch`、`80h`、`A0h` 和 `FCh`
處讀取 3、4、16 和 128 位元組，在 100 kHz 與 400 kHz 下均為各 30/30，資料與映像比對一致。從 I2C 模式下的
I3C 連接埠（每次傳輸都以 `7Eh` 標頭開始）進行讀取時，工作階段 1 中 30 次有 8 次正確；在工作階段 3 中，重設後的第一次
讀取被 NACK，第二次從 `00h:46-48` 傳回 `80 00 00`。

| 症狀 | 可能原因與處置 |
|---|---|
| 每次組合讀取都以 `FW_I3C_NACK_ADDRESS` 失敗 | 命令備妥太遲：檢查 DMA 中斷優先順序是否高於 I3C 中斷，以及其中是否執行了耗時的動作 |
| 128 位元組讀取失敗，分析儀顯示 308 個 SCL 時脈 | 讀取在 32 位元組處被截斷：主迴圈沒有供給傳送緩衝區。移除阻塞式 `printf` 及類似動作 |
| 讀取失敗後目標裝置停止回應，直到重設 | 接收一直被標記為進行中；韌體需要 `I3C1_Target_ReceiveCancel()` |
| 上電後的第一次初始化以 `FW_I3C_BUS_INIT_NACK_RSTDAA` 失敗 | 重設後的第一次傳輸被 NACK；請再次初始化 |
| MPLAB IPE 回報 "Connection Failed" 或 `Transmission on endpoint 2 failed (err = -150)` | 需要重新插拔 PKoB4 的 USB |
